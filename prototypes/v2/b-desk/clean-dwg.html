让 DXF 成为可被脚本干净解析的电气连接图

不要把“节点”和“连接”藏在自由文本或线段形状里，而要把它们分别放进 DXF 本身具有结构语义的图元中。DXF 提供了 INSERT、ATTRIB、BLOCK、LAYER 这些可被 ezdxf 等库直接按类型查询的结构化容器。脚本能否“干净地解析”，取决于你在作图时是否把电气事实写进了这些容器，而不是写进了几何外观。

以下按“节点—端口—连接—链路重建”的顺序，给出可直接落地的标准做法。

1. 先理解 DXF 中哪些东西可以被脚本“干净地查出来”

脚本最容易解析的 DXF 实体类型如下，作图时应把对应电气语义优先绑定到这些实体上：

DXF 实体 可携带的结构化信息 对应电气语义
INSERT（块参照） name（块名）、insert（坐标）、layer，以及通过 ATTRIB 挂载的任意标签-值对 一个节点/设备实例
ATTRIB（块属性） tag（属性名）+ text（属性值），以键值对形式附在 INSERT 上 节点的 稳定标识符、端口号、类型、模块归属
LAYER（图层） 图层名本身 连接线类型（信号线、电源线、总线）或节点类别
LINE / LWPOLYLINE 端点坐标、所在图层 物理连接线段（可选，仅用于几何对账）
BLOCK 内的几何 块定义内部的 LINE、ARC、TEXT 等 符号外形，脚本不应从中提取电气事实

ATTRIB 是这里最关键的东西。它把“这个节点是什么、有哪些端口、属于哪个模块”以可编程读取的键值对形式绑定在 INSERT 上，而不是散落在旁边的 TEXT 里。一个 INSERT 可以有零个或多个 ATTRIB，每个 ATTRIB 有明确的 tag 和 text。脚本遍历 modelspace.query("INSERT")，再读取每个 INSERT 的 attribs，就能拿到结构化的节点数据，完全不需要正则去猜“附近的文字是什么”。

2. 图层规范：用图层名编码“连接类型”，而不是让脚本从线段形状推断

规则：所有具有电气连接语义的线段，必须放在名称固定、可枚举的图层上；不要使用 0 层或随手命名的图层承载连接。

建议的最小图层集：

图层名（建议大写、可脚本匹配） 用途
CONN_SIGNAL 信号连接线
CONN_POWER 电源连接线
CONN_BUS 总线/多网络捆绑线
NODE_SYMBOL 节点/设备 INSERT 所在层（可选，节点身份主要由 ATTRIB 承载）
ANNO_NONELEC 纯注释、标题、说明，脚本明确忽略

脚本侧的对应逻辑极其简单：msp.query('LINE[layer=="CONN_SIGNAL"]') 或 msp.query('LWPOLYLINE[layer=="CONN_POWER"]')，就能一次性拿到该类连接的全部几何对象。图层名本身成为连接类型的第一层分类字段，不需要脚本根据线宽、颜色或线型去反推。

注意：图层名一旦确定就不要再改，也不要用“信号线1”“信号线-new”这类变体。脚本的过滤条件应当精确匹配，而不是模糊包含。

3. 节点与端口：用“块参照 + ATTRIB”承载全部身份信息

这是整条链路可解析性的瓶颈所在。一个电气节点（设备、连接器、端子排、模块实例）应当被画成一个 INSERT，其身份和端口信息通过 ATTRIB 键值对给出。

3.1 必须挂载的最小 ATTRIB 集合

每个节点类 INSERT 至少应携带以下 ATTRIB（tag 固定，text 为实例值）：

ATTRIB.tag 含义 示例值
NODE_ID 工程内唯一稳定标识符 N_0007 / UUID
REF 参考位号 U12 / J3 / X5
MODULE_ID 所属模块的稳定标识符 M_PWR / M_IO
PORT_01_ID 第 1 个端口的稳定端口 key P_TX
PORT_01_NUM 第 1 个端口的可见端口号 2 / A3
PORT_01_DIR 端口方向 IN / OUT / BIDIR
PORT_02_ID 第 2 个端口…… P_RX
PORT_02_NUM …… 3
PORT_02_DIR …… IN

关键原则：端口的脚本映射键使用 PORT_nn_ID，而不是使用显示文字。显示文字（比如 TXD）可以随文档语言或格式调整，但 PORT_01_ID = P_TX 是稳定的。端口号 PORT_nn_NUM 用于与外部网表、引脚号对账，但脚本内部建立连接时应优先使用 {NODE_ID, PORT_nn_ID} 这个组合键。

3.2 块定义中不要嵌入电气语义

BLOCK 定义内部的 TEXT 或 MTEXT 只应作为符号外观的一部分（例如画一个连接器框里的 1、2 标注）。脚本不应从块内 TEXT 提取端口号，因为同一个块定义会被多个 INSERT 复用，块内文字如果被当作数据，就无法区分实例。实例数据必须走 ATTRIB，这是 DXF 设计的本意：ATTDEF 在块定义中定义模板，ATTRIB 在 INSERT 上携带每个实例的具体值。

4. 连接关系的表达：让“谁连谁”成为可独立读取的记录

仅有节点和端口还不够，必须让脚本能找到 “端口 A 到端口 B 之间的电气连接”。DXF 没有原生网表，因此需要用一种与布局解耦的方式记录连接。

推荐方案：把每条连接作为一个轻量 INSERT，用 ATTRIB 显式声明两端

为“连接”定义一个专用的块，例如 CONNECTION。每个电气连接实例是一个 INSERT，携带：

ATTRIB.tag 值
NET_ID 该连接的稳定网络标识符（可选但强烈建议）
FROM_NODE 源节点 NODE_ID
FROM_PORT 源端口 PORT_nn_ID
TO_NODE 目标节点 NODE_ID
TO_PORT 目标端口 PORT_nn_ID
CONN_TYPE SIGNAL / POWER / BUS

这个 INSERT 的几何可以是一条示意线、一个点，甚至放在图纸边缘的“连接记录区”，脚本完全不依赖它的坐标。脚本只需查询 INSERT[name=="CONNECTION"]，读取每个 ATTRIB 的 FROM_* 和 TO_*，就得到了权威的端口到端口连接事实。

为什么不在脚本里靠“线段端点吸附”来推断连接

靠几何邻近推断连接是脆弱的：线段端点是否精确重合、是否被修剪、是否经过块的外框而非端口、是否存在跨页连接，都会让脚本陷入不确定。把连接事实写成 ATTRIB 键值对，几何线段退化为给人看的可视化提示，脚本的主数据源与布局彻底解耦。如果仍然希望保留几何对账，可以让脚本在读取 CONNECTION 记录后，再用 LINE 端点与 INSERT 的插入点做一致性检查，但判断依据永远是 ATTRIB，不是坐标邻近。

5. 脚本重建链路的干净流程

在按上述规范作图的 DXF 上，脚本可以按固定顺序完成链路识别，全程无需正则、无需距离阈值、无需猜测图元含义：

第一步：建立节点索引。 查询所有 INSERT，对每个 INSERT 读取 attribs，构造 NODE_ID → {REF, MODULE_ID, ports: {PORT_ID → {NUM, DIR}}}。非节点块（如 CONNECTION、标题栏）通过 NODE_ID 是否存在来区分；没有 NODE_ID 的 INSERT 跳过或归入“非电气图元”。

第二步：建立连接边。 查询 INSERT[name=="CONNECTION"]，读取每个实例的 FROM_NODE / FROM_PORT / TO_NODE / TO_PORT。用第一步建立的节点索引验证两端节点和端口是否存在；不存在的组合标记为未解析连接，而不是静默丢弃。

第三步：形成链路。 将连接边按 NET_ID（如果有）分组，或在无显式 NET_ID 时用并查集按 {NODE_ID, PORT_ID} 合并，得到从任意端口出发的连通分量。连通分量的大小、路径、端点方向均可从节点索引和连接边直接导出。

第四步（可选）：几何对账。 仅当需要检查“图上画的线是否与逻辑连接一致”时，再用 LINE 端点与节点 INSERT 的插入点做距离容差匹配。这一步是验证，不是发现；即使跳过几何对账，链路仍然完整。

6. 必须守住的作图纪律（否则脚本前功尽弃）

第一，节点身份只用 ATTRIB，不用邻近 TEXT。 一个写在块旁边的 TEXT 无论离得多近，在 DXF 数据模型里都与该 INSERT 没有绑定关系。ATTRIB 才是绑定在 INSERT 上的键值对。

第二，PORT_nn_ID 的 n 使用定宽两位数字（PORT_01_ID、PORT_02_ID……），不要使用 PORT_1_ID 与 PORT_01_ID 混用。定宽使脚本可以枚举 PORT_01_ID 到 PORT_99_ID，而不会漏掉 PORT_10_ID 这类“字符串排序在 PORT_2 之前”的陷阱。

第三，连接记录使用独立的 CONNECTION 块，不与节点块混用。 节点块的 ATTRIB 描述“我是谁、我有哪些端口”；连接块的 ATTRIB 描述“谁连到谁”。两者职责分离，脚本的查询条件才能保持单一和确定。

第四，图层名和 ATTRIB.tag 一经确定就作为工程常量冻结。 脚本的过滤条件是精确匹配；如果允许人为改名或使用大小写变体，解析就会断裂。这一纪律与 IPC-2612 所强调的一致的命名约定和原理图属性标准是同一方向上的要求。

7. 如果必须在现有工具链中落地：一条可操作的导出前检查清单

  1. 所有电气节点是否都是 INSERT，且至少携带 NODE_ID、REF、MODULE_ID 以及按定宽编号的 PORT_nn_ID / PORT_nn_NUM / PORT_nn_DIR？ 任何只靠旁边 TEXT 标注的节点都不合格。
  2. 所有电气连接是否都有对应的 CONNECTION INSERT，且 FROM_* / TO_* 四元组完整？ 只有线段没有连接记录的，脚本不认。
  3. 承载连接线段的图层是否只有 CONN_SIGNAL / CONN_POWER / CONN_BUS（或你冻结的同义固定集）？ 非电气线条是否全部在 ANNO_NONELEC 或明确忽略的图层上？
  4. 是否存在任何“靠坐标邻近才能理解”的端口或连接？ 如果有，回退去补 ATTRIB，不要指望脚本做几何推断。
  5. 导出 DXF 后，用 ezdxf 快速验证：msp.query('INSERT') 的数量是否与预期节点+连接数吻合；抽样一个 INSERT，其 attribs 的 tag 是否恰好是冻结的键集合。这一步能提前暴露“块属性没有随导出保留”之类的问题。

做到这五条，DXF 中的电气事实就已经是按键值对和固定类型可查询的结构化记录，而不是需要脚本用启发式规则去“读图理解”的图形堆叠。链路识别成为一次确定性的索引与合并操作，干净且可重复。
